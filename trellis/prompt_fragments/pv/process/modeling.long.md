## Modeling and goal stating (Phase 0)

Modeling and goal stating produces Lean statements faithful to the supplied GOALs about the source program. The source determines behavior; GOALs determine what must be expressed. Proof work in this phase establishes model preservation and its supporting facts independently of the GOALs' truth. Proving, disproving, and classifying GOALs belong to argument development. Work begins with the mechanically extracted model and available libraries, adding only the source adaptations and model content needed for those statements.

Setup chooses packaging, toolchain support, and program configurations and instances appropriate to the GOAL scope. These choices identify the program being modeled; adaptations preserve its relevant behavior. It ends with audit approval of a successful Cargo build, valid extraction configuration, and short notes justifying the package correspondence and extraction scope. Adaptation addresses extraction obstructions and introduces needed observation interfaces. Its audit requires code comments establishing preservation independently of unresolved correctness claims, successful Aeneas extraction, and a full Lean check that passes or fails solely for diagnosed missing model definitions. The reviewer directs worker bursts in each stage.

For an unsupported primitive, preparation tests a supported call form or narrow extraction boundary, using existing libraries where possible. Choices account for source edits, model definitions, and preservation proofs. Equivalences introduced by changing the computation are assessed against cheaper adequate alternatives before adaptation approval; missing operation meanings are recorded separately. Preservation retains each affected GOAL's source observations on its input domain. Setup records the source subjects, domains, and observations corresponding to the GOAL vocabulary; unresolved ambiguity is reported for audit.

After adaptation, workers state each GOAL faithfully in paired NL and Lean, adding the definitions and native model bindings needed for that purpose. Each authored model definition carries explicit preservation claims with NL proofs and a separate application to every pursued GOAL. Preamble carries the claims for setup and source adaptations, using the preparation notes and code comments. These prove-only arguments justify modeling choices; shared paired lemmas can supply support. Mechanically extracted declarations retain their provenance-based treatment.

Correspondence checks Lean against paired NL meanings. Goal-faithfulness checks the supplied GOALs against the NL statements through their definitions and preservation claims. Soundness checks preservation proofs and their support. Substantiveness judges whether the authored content and decomposition are useful.

Completion requires elaborated statements covering every pursued GOAL, reproducible extraction, and complete model definitions. Preparation audits, correspondence, substantiveness, goal-faithfulness, required soundness, and required route approvals must be current and passing. Final audit approves completion; outside-expert review of the model, scope, and goal meanings then authorizes argument development.
