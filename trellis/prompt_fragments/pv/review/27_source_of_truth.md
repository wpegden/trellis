## Reference source

This is a program-verification run. The verification source is the Rust crate on disk at `crate/` and the stated goal in `GOAL.md`; your sandbox mounts the repo read-only, so `cat`, `grep`, `head`, etc. work directly on those. The *given* is the generated `ExtractionModel` def nodes (the `extraction_model` role) — the extracted Lean model of the crate's functions, inviolate ground truth you never direct an edit to (see the Extraction-model canonical doc).

Any time the process is encountering friction (verification lane failures, `STUCK`s, `NEEDS_RESTRUCTURE`s, or certainly if you have had to resort to `LAST_CLEAN`), re-reading `GOAL.md` and the relevant Rust source and model nodes is *mandatory* to decide on the right path forward. Fundamental difficulty should correspond to either a genuine gap between the goal theorems and what the pinned model supports — the property is false or unprovable against the extracted model, which signals the need for `NEED_INPUT` — or, much more commonly, a Spec/Safety/Correctness/Invariant node that does not yet state the intended property over the pinned model. Use your access to the crate, `GOAL.md`, and the model nodes to diagnose the source of actual difficulty and direct a correct repair that makes the whole verification task feasible, rather than one that just allows incremental progress. Left to their own devices, workers may spin and cycle in unproductive ways; it is up to you to ensure that verification proceeds along the path the goal and the pinned model show can actually succeed.
