## Adjudicating an extracted-model refutation

Re-derive the supplied witness against the exact registered target in the
byte-pinned Lean model. The carrier and verifier prose are routing evidence;
only ordinary checked closure establishes the formal result.

When the witness motivates pursuing the exact model negation, use the existing
recovery route: `confirm_need_input: false`, `under_model_ruling: ""`,
`set_live_polarity: "disprove"`, and `set_live_polarity_target` set to the
primary target id. Supply at least one focused Lean proof task. This route is
available even when the witness is physically unrealizable. Keep the source
eligibility diagnosis in the report; do not assign `bug` merely to select a
formal proof direction. Ordinary importer and exact-negation checks still apply.

If the derivation fails, explain why and supply ordinary recovery tasks; a
rejected witness is not evidence that the positive theorem is proved. A
conditional proposal is independent and can be submitted in a separate response.

Source classification and formal direction are distinct. A source-bug claim
requires the configured authenticated source evidence. Describe dropped language
invariants or extraction divergence accurately, using the existing assumption
or seam-repair lanes only where their own contracts permit them. In trust
protocol v2, `under_model_candidate_invariant` must be empty; in earlier protocols
it is used only for an explicit assumption-authoring request. Neither a model
counterexample nor a conditional theorem certifies a real Rust execution.
